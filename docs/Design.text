# UNO Multiplayer Platform - System Design & Architecture

## Vision

Build a production-grade UNO platform demonstrating senior-level Full Stack Engineering skills.

The application must support:

* Offline-first gameplay
* Guest users
* Registered users
* Online multiplayer
* Realtime synchronization
* Cross-platform mobile support
* Scalable backend architecture
* Event-driven design
* Enterprise-level code organization

The goal is not merely to build a card game but to showcase architecture, scalability, maintainability, testing, and distributed-system concepts.

---

# Core Functional Requirements

## Guest Mode

Users can:

* Launch app without registration
* Play single-player UNO
* Save progress locally
* Track local statistics
* Continue playing offline indefinitely

No backend dependency is required.

---

## Registered User Mode

Users can:

* Sign up
* Login
* Sync data across devices
* Access multiplayer features
* Maintain persistent profile and statistics

---

## Offline First

The application must continue functioning when:

* Internet is unavailable
* API is unavailable
* Backend services are down

Single-player gameplay must never depend on server availability.

---

## Multiplayer

Users can:

* Create rooms
* Join rooms
* Start matches
* Play in realtime
* Reconnect after temporary disconnects

Communication occurs through Socket.IO.

---

## Synchronization

Offline activity must eventually synchronize.

Examples:

* Offline games
* Statistics
* Achievements
* User progression
* Match history

Sync occurs automatically when connectivity returns.

# Package Responsibilities

## shared-types

Contains:

* DTOs
* Contracts
* Events
* Socket payloads
* Shared interfaces

No business logic.

---

## uno-engine

Pure game engine.

Contains:

* Game rules
* Move validation
* Turn calculation
* Winner detection
* Card effects

Must be deterministic.

No database.

No network.

No framework.

---

## api

Responsibilities:

* REST APIs
* Socket.IO
* Authentication
* Persistence
* Synchronization
* Multiplayer orchestration

Does not contain UNO rule logic.

---

## mobile

React Native + Expo.

Responsibilities:

* UI
* Local storage
* Offline persistence
* Sync orchestration
* Multiplayer interaction

# Backend Managers

## RoomManager

Responsibilities:

* Create room
* Join room
* Start room game
* Validate room state

Storage:

Map<roomId, Room>

Current implementation is in-memory.

Future implementation:

Redis + Database

---

## GameManager

Responsibilities:

* Create game
* Retrieve game
* Process move
* Update state

Storage:

Future implementation:

# Offline First Architecture

Local database is source of truth while offline.

Examples:

* AsyncStorage initially
* SQLite later

All user actions generate local events.

Examples:

GamePlayed

AchievementUnlocked

ProfileUpdated

StatisticsChanged

These events are queued.

When internet returns:

Sync Engine
↓

Upload Pending Events
↓

Backend Processes Events
↓

Server Acknowledges
↓

Queue Cleared
